# U30 Air 调度省电与 CPU0 深睡开关（2026-10-24）

已按用户指定的五项内容修改 MU300 `clean-tf-7.2` 分支，并部署到当前连接的 U30 Air。E5 仓库同步了 CPU0 深睡网页开关及其共同打包路径，未部署到 E5 系设备。

## 改动范围

1. CPU 页面新增「CPU0 深度休眠」开关。通过实际设备树中的 `sprd,ums9620` 与 CPU0 空闲状态名识别 T157/T760 平台，只调整 CPU0 的 `core-sleep-*`、`cluster-pd`；不调整 WFI 和其他核心。T158/UMS9621 隐藏开关，直接调用写接口也会拒绝。修改即时生效并保存，启动时重放；没有保存选择时保留已有启动策略。
2. 灯效采用截止时间提示与状态变化触发。稳定时不再每五秒启动 LED shell；充电时至多三十秒核对一次，其他情况至多九十秒，睡灯截止时间与按键/电源事件仍可提前触发。保留本分支 U30 Air 的颜色边界、硬件呼吸曲线、充电常亮、拔线后超时熄灯及单一灯效控制者。
3. 温控检查根据距离阈值自适应。报警中、恢复限频中及读取异常时维持五秒；由脚本负责限频时最长十秒，确认内核散热绑定接管时最长三十秒。保留原阈值、紧急关机和用户频率上限恢复规则。旧 shell 温控守护也同步此节奏。
4. 调度守护和短信/联网/IPv6 事件接收的空闲等待使用 500 ms timer slack。事件到来仍可立即唤醒；子进程动作恢复原精度，原始单调时钟截止时间不变。设置容差失败不退出功能服务，继续使用原有精度。
5. 启动日志直接读取最近 300 条，过滤既有 `PR_CAPBSET` 噪声；前九十秒保持两秒采集，此后改三十秒。总采集时长和持久化写入边界不变。

调度思路参考本地已固定的 `liuwang97/mu300-linux` 分支快照（`cpu-load`：`b7474ed2c152ec1fd94b5a0ceaab3a4d8c1339cb`），按本分支已有按键、灯效、温控和双卡逻辑适配。分支审计见 `LIUWANG97-POWER-COMPARISON-20261024.zh-CN.md`。本次未额外合入该 fork 的其他基带收集改动。

测试使用独立 ARM64 OpenWrt 容器，不代表设备冷启动、长时间待机或实际短信通话的硬件验证。测试初期发现容器缺少 ubus 运行目录、完整 flock/usleep 等环境条件，已补足后重测；另修复 timer slack 写入被内核拒绝时触发 `set -e` 退出的问题，相关回归随后通过。
