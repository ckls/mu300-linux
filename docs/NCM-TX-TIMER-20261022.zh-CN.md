# NCM USB 共享在负载后延迟升高：静态排查（2026-10-22）

## 已确认的源码缺陷

两仓库实际使用的 `f_ncm.c` 中，`ncm_tx_timeout()` 都忽略
`ndo_start_xmit(NULL, netdev)` 的返回值。`u_ether.c` 在 USB TX 请求耗尽时返回
`NETDEV_TX_BUSY`，此时还未调用 wrap、聚合 NTB 仍在。但定时器返回
`HRTIMER_NORESTART`，没有 qdisc 替这次 NULL-skb 的定时发送重新排队。
因此待发 NTB 可以滞留，等待新流量触发再次打包，或填满才发送。

这与长时间使用中经历吞吐突发后卡顿相容，但不是一个按 uptime 自动增长的定时问题。
目前没有群友故障现场的网关/外网对照和 USB 请求轨迹，不能认定该缺陷解释所有反馈，
也没有证据认定为内存泄漏、主机选择性挂起或基带延迟。

## 修复依据与范围

采用 Linux USB 邮件列表 Cosmin Tanislav 2026-08-17 的修复思路：
https://lore.kernel.org/linux-usb/20260817192638.437798-1-cosmin-gabriel.tanislav.xa@renesas.com/
邮件备份：https://lkml.indiana.edu/hypermail/linux/kernel/2608.2/02481.html

仅在 `NETDEV_TX_BUSY` 时把下一次到期时间推进原有 300 微秒，再返回 RESTART。
不能只返回 RESTART 而不推进过期时间，否则可能造成过期定时器反复立即触发。
成功发送或 netdev 已断开时不重试；没有新增常驻轮询服务。
不修改 USB 枚举、DHCP、聚合大小、充电、USB 休眠、CPU 调度或蜂窝 AT。
该补丁与此前 pseudo-header 校验和修复不同，后者不处理定时器请求耗尽。

- E5：`devices/common/usb-ncm.py` 接入 E5、M8、T551M 公共准备入口；
  T512N 继承 T551M，远航 41S、K1 继承 M8，六机型覆盖。
- MU300：`0025-usb-ncm-retry-busy-timer-flush.patch` 经现有通用补丁循环加载，
  同时覆盖 6.18.54、7.2.8 和各机型；保留原有小包立即发送优化。
- E5 基准源码仍有正常的 300 微秒聚合等待。此次没有因其不同而额外改动小包策略。

## 验证结果与限制

在临时目录复制实际驱动文件并应用修复，提取真实回调编译为 C 测试：
断开、成功发送、连续 10000 次 BUSY、请求恢复后的成功发送均通过。
每次 BUSY 都验证新到期时间严格晚于当前时间，成功/断开后不继续重试。
E5 公共修复重复应用一致；MU300 两个实际准备树均应用和测试通过。
测试未修改现有内核缓存、发行包或实机。

本次旧管理地址无法连接。尚未实机复现，也未编译新内核或打包部署，
因此不能把测试通过称为已解决群友的长时间运行故障。
后续实测应对照 USB ping 网关、设备反向 ping 主机、USB 吞吐和外网 ping；
网关正常而外网升高时，应查蜂窝/上游路径而不是继续修改 NCM。

## 深入回归（同日）

新增 `ncm-tx-fixture.h`，提取实际 `u_ether.c` 的 `eth_start_xmit()`、
`tx_complete()`、过滤判断及实际 NCM 定时回调共同编译。请求完成由测试显式调度，
锁和 NTB 封装使用测试替身，不称为真实多核并发或 USB 电气层验证。

覆盖：

1. 没有 USB 请求时，普通 skb 未被释放；NTB 等待状态保留。
2. 请求归还后，不依赖新网络包即可刷新 NTB；完成后请求归还、队列唤醒、计数平衡。
3. 正常聚合暂存时，借用的请求立即归还，不误计丢包。
4. USB 提交失败、完成时 ESHUTDOWN：数据释放一次，请求不泄漏。
5. 重试前聚合数据已被其他发送清空：一次空刷新即停止，不继续重试。
6. generic gether suspended 分支返回 BUSY 后恢复，可正常继续发送。
   实际三个 NCM 实现目前没有注册 gether_suspend/resume 回调；该项为防扩散测试，
   不等于验证主机系统的选择性挂起行为。
7. BUSY 后断开，及回调已经读到 netdev 但 port 已置空的确定性交错：停止重试。
8. 负向对照移除实际修复，断言稳定失败于 BUSY 刷新；禁止生成 core 文件。

E5 基准及 MU300 6.18.54 / 7.2.8 的两组 C 程序均在 ASan、UBSan 下通过。
NCM 测试兼容未应用/已应用补丁的准备树；E5 标准多机型构建器增加此项回归。
MU300 原有 USB 管理测试 23 项通过；其中旧 TF 启动顺序断言仍匹配旧版连续文本，
本次更新为验证当前 GPT 根挂载、策略读取、条件枚举和旧镜像挂载的实际先后关系，
没有修改 boot/init。E5 USB 管理的设备发现、异步角色、协议切换测试通过。

功耗边界：重试仅发生在聚合定时器触发且发送返回 BUSY 时，保持 300 微秒间隔；
成功、断开后停止，卸载仍经 hrtimer_cancel 同步取消。但若主机长期不接收、请求
长期耗尽，仍可能每秒触发约 3333 次重试，不能据离线测试保证这种状态的功耗不变。
此次不禁用 USB 休眠，也不擅自更改为其他退避间隔。真实负载、挂起功耗及长期运行
仍需带修正版内核的实机验证；现有发行包和设备尚未更新。
