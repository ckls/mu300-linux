# 修改管理地址后旧 192.168.77.1 仍可访问

已确认代码缺陷：preinit 使用临时 `192.168.77.1`，LAN 接管时却只删除与当前桥地址相同的 USB 地址。用户更换网段后，临时地址不再与桥地址相同，因此残留在 usb0/rndis0 上，继续作为 Linux 本机地址响应。

修复公共 `10-mu300-usb` 交接脚本：处理 `lan/ifup` 与 `lan/ifupdate`；在桥具备 IPv4 后，清理已桥接 USB 成员上的全局 IPv4，让 `/etc/config/network` 管理的 LAN 地址仅归属 br-lan。保留未桥接接口、桥上的用户地址及 IPv6。不增加轮询、USB 重枚举或链路关闭。

验证：`test_upstream_stability.py` 6 项、`test_usb_management.py` 23 项通过。另在隔离 Linux 网络命名空间中运行实际交接脚本，确认启动及地址更新后旧本机路由消失、新桥地址和额外地址、IPv6、链路保留。E5 仓库同时修复其默认第二管理地址及旧配置迁移。

尚未实机修改地址验证，未部署、未重新打包。早期启动/救援阶段仍可临时使用默认地址；正常 LAN 接管后应移除。
