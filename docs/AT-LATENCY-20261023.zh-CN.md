# AT 终端等待调整

`mu300-modemd` 在正常回复后的每次命令前等待通道安静，原值为 100 ms，现为 50 ms。超时后的 1000 ms 隔离、最大排空时间、单一物理 owner、SIM 序列互斥和原有重开条件不变。前端 AT RPC 设置 `nobatch`，避免交互命令额外等待合批。

网页记录的是 HTTP/RPC、脚本、命令队列和模组响应的总时间。用户反馈的 209–226 ms 不能全部归因于模组；本次确认并减少了固定排空等待及合批等待，没有将页面数字改成较小的虚假值。

在已有 `mu300-event-tests` 原生测试环境运行 `test_modemd`，35 项全部执行通过，包括新增的 50 ms 正常派发测试、迟到回复与超时、短信事件、SIM 缓存、互斥和 ubus 收集。日志：`out/build-logs/20261023-081022-modem-at50-native-93057/command.log`。最初宿主机缺少 ucode 的运行跳过了测试，未算作成功验证；上述结果来自实际执行的容器测试。

本轮没有连接 MU300 实机，没有断言其网页或基带往返已降至 50 ms，也没有修改设备、构建发行包或提交 Git。需要后续实机验证端到端延迟及长期运行稳定性。
