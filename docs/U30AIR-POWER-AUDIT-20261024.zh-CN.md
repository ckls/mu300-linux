# U30 Air 省电只读检查（2026-10-24）

## 结论

当前没有看到占满核心的后台进程或明显 CPU 空转。主要省电取舍是：

1. 既有低延迟策略仍禁用 CPU0 的 core-sleep/cluster-pd，CPU0 空闲时主要停在 WFI。
2. 管理网页实时刷新增加 CPU 和唤醒开销，关闭后明显下降。
3. 当前内核未启用整机 suspend；CPU idle 与整机 suspend 必须分别看待。

本轮只检查，不修改设备设置、服务、内核、无线或充电参数；没有为省电回滚此前修复。
不能由本次短时 CPU 采样推算续航改善百分比或整机功率。

## 设备和方法

- 经既有 SSH 公钥固定记录、机型和设备身份核验，确认 U30 Air，OpenWrt，内核 7.2.8。
- 经 USB 的 `192.168.77.1` 连接，热点和蜂窝维持工作；采样期间流量较小。
- 第一阶段用户管理网页开着；用户确认关闭管理页后，补测第二阶段。
- 每阶段三次读取、间隔约 20 秒，覆盖约 40 秒。读取 CPU、进程 ticks、cpuidle、
  cpufreq、IRQ、网络计数和电源 sysfs；采样间隔远端 Python 休眠，未做高频追踪。
- Python 采样器本身约占单核 0.6%～0.7%，SSH/USB 和采样造成的开销仍包含在结果内。
  仅有前后各一段，不是反复 A/B/A 或电池独立供电实验。
- 两阶段均验证配置文件 SHA-256 和 boot ID 不变。没有执行 AT、切卡或触碰 NV。

## CPU 和后台进程

百分比口径：下表整机值以八核总容量为 100%；进程值以单核容量为 100%。

| 条件 | 整机忙碌比例，两个约 20 秒窗口 | rpcd，单核比例 | mu300-modemd，单核比例 |
| --- | --- | --- | --- |
| 管理页打开 | 1.528%、1.812% | 4.322%、4.469% | 1.739%、2.085% |
| 用户关闭管理页后 | 0.626%、0.551% | 两窗口均未增加 CPU tick | 约 0.050%、0.050% |

页面关闭后的 CPU 忙碌折合单核约 4.4%～5.0%，包含内核、转发、全部服务与采样器，
不能把它写成单个常驻服务占用。闭页后的 ndp-learn shell 约为单核 0.70%～1.09%，
sysd/traffic 约 0.20%～0.25%，AT bridge 约 0～0.05%；没有据此认定 IPv6 路由服务有忙循环。
进程等待点显示 NDP/bridge 在 poll、主要 ucode 服务在 epoll。

管理页关闭后 arch_timer 和广播定时器 IRQ 也减少，未见 USB NCM 每秒数千次重试的迹象。
Wi-Fi/蜂窝存在少量真实流量，因此这些窗口不是完全无业务的实验室待机。

## 空闲和频率

- 三个 cpufreq domain 都是 schedutil，未见配置锁定最高频。
- CPU0 三个状态的 disable 均为 1，但安全回退仍实际使用 WFI：页面打开时 WFI
  驻留约 95.2%～96.6%，关闭后约 98.2%～98.8%；core-sleep 和 cluster-pd
  在两阶段都没有新增进入次数。不能把 disable=1 写成 CPU0 一直忙等。
- 其他核仍进入深层 idle；首轮 CPU7 cluster-pd 驻留约 99.2%。
- CPU7 的 scaling_cur_freq/time_in_state 显示 1.703 GHz，但同阶段实际深睡约 99%，
  cpuinfo_cur_freq 曾读到 26 MHz；请求频率/驻留记账不能当成持续有功运行频率。
- 先前为降低延迟引入的 `mu300-lowlatency` 仍执行。这是既有用户选择，
  本次未擅自撤销，也未把它归咎于近期部署的异常。
- `ums9620_lpintc` 已加载。此前 USB 实验已证明允许 CPU0 cluster-pd 时它能改善
  唤醒延迟，但本轮没有改变 idle 或完成 Wi-Fi/USB/电池功率的新一轮 A/B。

优先可评估的优化是：保留 LP_AP_INTC，复测允许 CPU0 深层 idle 的延迟和功率，
再提供明确的低延迟/省电选择。现有数据不足以承诺无延迟代价或具体节省多少电量。

## 整机与外设电源边界

- 实机配置为 `CONFIG_NO_HZ_IDLE=y`、`CONFIG_PM=y`、`CONFIG_HZ=250`，
  `CONFIG_SUSPEND` 和 `CONFIG_PM_DEBUG` 未启用，`/sys/power/state` 为空。
  这是当前内核能力边界，不能通过网页开关直接补出可靠的整机 suspend。
- USB 数据连接和 Wi-Fi 热点开启时，DWC3、PCIe/WCN 等 runtime PM 节点处于 active；
  部分 control=on。该快照不证明外设无流量或拔线后也不会省电，不能直接强制改 auto。
- 电池约 33%～34%、25.5～25.6°C，系统测得温区约 47～49°C，无须为本轮检查改温控。
- 当前 USB 在线且充电，BQ 输入电流上限为 500 mA；FGU 净充电电流样本约 +15～+94 mA。
  此为电池侧净电流及软件输入预算，不是 USB 功率计结果，也不是电池独立供电的负载电流。
  本次未重新排查或修改既有充电协商策略。
- 电池灯使用内核 pattern 触发；没有据此认定存在用户态软件呼吸动画空转。
